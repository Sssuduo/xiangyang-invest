# V16.16.25 — 工作日历：事件卡「看不清」根因修复 + 相邻两列悬停卡被挤掉

> 日期：2026-09-18 | 涉及文件：`frontend/src/views/WorkCalendarView.vue`（前端单文件，无后端改动）

## 一、问题现象

1. **事件卡看不清**：工作日历周/月视图中事项卡只能隐约看到 emoji（🏷 / 🖼 / 👥），时间、事项名、内容、参加人员几乎不可见；卡片没有底色和边框，像"透明贴纸"。
2. **相邻两列事项的悬停卡一闪而过**：当两个事项在相邻列（或同一天并排两列）紧挨着时，把鼠标停在**左侧**事项上，悬停预览卡出现后立刻消失/跳走，无法停留下来点「✎ 编辑」或看图片。

## 二、根因

### 2.1 事件卡看不清 —— Vue scoped 样式从未命中事件卡（真因）

FullCalendar 6 的 `eventContent` 返回的是 **HTML 字符串**，由 FullCalendar 自己 `innerHTML` 注入到 `.fc-event-main` 里。
这些节点**不带** Vue 编译器打在模板元素上的 `data-v-xxx` 属性，而本组件是 `<style scoped>`：

```css
.calendar-event-card { background: rgba(102,126,234,.22); color: #22304f; }  /* 旧写法 */
/* 编译后 → .calendar-event-card[data-v-xxx] { ... }  ← 永远匹配不到注入的节点 */
```

实测（生产页面 eval）证据：

- `.fc-event-main` 下的 `.calendar-event-card` 的 `getAttributeNames()` 只有 `["class"]`，**没有 `data-v-*`**；
- 该卡的 computed `background-color` = `rgba(0,0,0,0)`（透明的）、`border-width` = `0px`、`font-size` = `13.6px`（FullCalendar 的 `.fc-event{font-size:.85em}`，说明我们写的 `12px` 也没生效）；
- 文字色被 `.fc-event-main` 的白色继承下去 → **白字落在透明底上**，只剩深色 emoji 可见。

也就是说：v16.16.19 → v16.16.24 期间所有「调透明度」的改动（0.10 / 0.16 / 0.22 / 0.26）**全都没有真正上过屏**，用户看到的始终是"几乎看不到"。而 `.work-calendar :deep(.fc-event)` 这类规则是能生效的（`.work-calendar` 是 FullCalendar 组件根节点，带 `data-v-*`），这就是"网格被改成透明了、但卡片样式没进来"的原因。

### 2.2 悬停卡一闪而过

原实现（`eventMouseEnter` / `hoverStyle` / `eventMouseLeave`）有三处隐患叠加：

1. **定位方向撞上相邻事项**：卡片固定放在事件卡右侧 14px 处（`left = rect.right + 14`）。相邻列事项与它只隔 FullCalendar 的 8px inset 间距，所以卡片总是压在右侧那个事项上。指针想移进卡片，必须**先掠过右侧事项**——这会触发右侧事项的 `eventMouseEnter`，把卡片内容/位置改到右边那个事项上，卡片就"跳走"了。
2. **延迟关闭定时器互相抢**：`eventMouseLeave` 里每次 `setTimeout(120ms)` 都是**新建**定时器、从不取消。上一个事项遗留的定时器会在新卡片刚出现时把它关掉，表现为一闪而过。
3. **`hoverStay` 残留**：进入卡片后置 `true`，但切换事项时不会重置；`eventClick` 把 `hoverStay` 置 `true` 后，卡片会永久挂在屏幕上不再自动关闭。

## 三、修复

### 3.1 样式：事件卡全部规则改用 `:deep()`

```css
/* 组件根节点 .work-calendar 带 data-v-*，:deep() 编译为
   .work-calendar[data-v-xxx] .calendar-event-card  →  能命中 FullCalendar 注入的节点 */
.work-calendar :deep(.calendar-event-card) { ... }
.work-calendar :deep(.event-title) { ... }
.work-calendar :deep(.ev-c0) { ... }
.work-calendar :deep(.ev-tag-g) { ... }
```

同时按「看清楚」重调了颜色与透明度：

| 项 | 旧值 | 新值 |
|---|---|---|
| 卡面底色 alpha（8 组 fallback）/ 标签色 | 0.22 ~ 0.26 | 0.34 ~ 0.42（浅色系 c1/c4 额外加深） |
| 边框 alpha | 0.48 ~ 0.52 | 0.72 ~ 0.80 |
| 事项标题色 | `#22304f` | `#131c36`（更实） |
| 时间 / 内容 / 人员 | `#4a5b7d` / `#5a6b8c` | `#2c3a5e` / `#3a4867` / `#46527a` |
| 左侧色条 | 与底色同色 | 保持实色 4px |

构建产物核对（lightningcss 会把 rgba 压成 hex8）：`background:#4caf505c`（=0.36）、`border-color:#388e3cc7`（=0.78）。

### 3.2 悬停卡：可长期停留

- `hoverPos` 由「鼠标坐标」改为记录**事件卡 rect**（`left / right / top`）。
- 定位策略：右侧放得下就贴右侧，否则向左展开；**两个方向都与事件卡重叠 2px**（`HOVER_CARD_OVERLAP`），指针横向移出事件卡时直接进入悬停卡，不再掠过相邻事项；两侧都不够时贴视口夹紧，整卡不再被挤出屏幕。
- 延迟关闭改为**全局唯一定时器** `hoverHideTimer` + `clearHoverHideTimer()`：显示卡片、进入卡片、打开编辑器前一律先清掉。
- 同一个事项重复 `mouseenter`（卡片覆盖邻居时浏览器会重放）只取消定时器，不重排、不重置停留态。
- 切换事项时重置 `hoverStay`；`eventClick` 不再强制 `hoverStay = true`（避免卡片永久驻留）。

## 五、经验小结

> **给 FullCalendar / 任何"注入 HTML 字符串"的第三方组件写样式，必须用 `:deep()`（或全局样式块），不能用裸类名。**
> 这类 bug 的典型特征是「样式改动毫无效果、调参调了半天没反应」——遇到时先用浏览器 eval 查目标节点的 `getAttributeNames()` 有没有 `data-v-*`，比反复微调数值有效得多。
