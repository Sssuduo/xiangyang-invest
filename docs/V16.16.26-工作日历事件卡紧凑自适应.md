# V16.16.26 — 工作日历事件卡：标签挪到时间段行 + 按可用宽高自适应精简

> 日期：2026-09-18 | 涉及文件：`frontend/src/views/WorkCalendarView.vue`（前端单文件，无后端改动）

## 一、需求

1. **标签的小图标挪到与时间段平齐的一行**（原来是第二行，占掉一整行）。
2. **同一时间段有多个事项时自适应**：卡片按可用空间自动精简内容，可以略去「参加人员」这一行，避免卡片之间拥挤、文字被截半。

## 二、改动

### 2.1 结构：第一行 = 时间段 + 图片数 + 标签徽章

```html
<div class="event-time">
  <span class="event-time-range">08:30-12:00</span>
  <span class="event-meta">🖼 1 <span class="event-tag-badge">🏷<span class="event-tag-name">参加会议</span></span></span>
</div>
<div class="event-title">…</div>
<div class="event-content">…</div>
<div class="event-participants">…</div>
```

- 时间段 `flex: 0 0 auto`（永不被压缩）；徽章 `flex: 0 1 auto; min-width: 0`，空间不够时自己省略。
- 标签名单独包一层 `.event-tag-name`：卡片变窄时先只留 🏷 图标，不再出现被截半的文字。
- 行高实测：时间行 15px（带徽章 17px）、标题 18px、内容 15px/行、人员 16px、内边距 8px。

### 2.2 自适应：以事件容器做尺寸查询

```css
.work-calendar :deep(.fc-timegrid-event-harness) { container-type: size; }
```

`eventContent` 注入的节点不带 `data-v-*`，所以容器查询规则同样必须带 `:deep()`（见 V16.16.25 记录）。
阈值 = 上一级内容刚好放下的高度，保证不出现「半截行」。

| 条件 | 卡片表现 | 需要高度 |
|---|---|---|
| 默认 | 时间行 + 标题 + 内容 2 行 + 人员 | 91px |
| 高 ≤ 90px | 略去参加人员（需求点 2 的主要动作） | 75px |
| 高 ≤ 74px | 内容压到 1 行 | 60px |
| 高 ≤ 59px | 略去内容，只留时间 + 标题 | 43px |
| 高 ≤ 42px（30 分钟级） | 时间与事项名**并排一行**，不显示徽章 | 24px |
| 宽 ≤ 165px | 略去参加人员（并排分列变窄时） | — |
| 宽 ≤ 152px | 标签徽章只留 🏷 图标 | — |
| 宽 ≤ 140px | 内容压到 1 行 | — |
| 宽 ≤ 112px | 整组图标（🖼 / 🏷）隐藏 | — |
| 宽 ≤ 95px | 略去内容 | — |

## 三、验证（本地 dev server 代理生产 API + agent-browser 实测）

| 场景 | 结果 |
|---|---|
| 9月11日下午 3 个事项（14:30-16:00 / 16:00-17:00 / 17:30-18:00） | 16:00-17:00（68px）自动略去人员行、内容压 1 行；17:30-18:00（34px）时间与事项名并排一行，拥挤消失 |
| 真实周（9/7-9/13，8 个事项） | 102px 卡片保留全部 5 行；170/238/586px 卡片完整 |
| 并排分列（同一天 2 列 / 3 列） | 180px 全显示；120px 只留 🏷 图标 + 1 行内容；90/60px 只留时间 + 事项名 |
| 窄列文字裁切检查 | `timeW=65 / timeScroll=65`、`meta=24`，无裁切 |
| 月视图 | 卡片正常（标签同样在第一行），行数比改动前少一行 |
| `container-type: size` 副作用 | 事件容器宽高与改动前一致（586/238/170/102/68/34），未破坏 FullCalendar 布局 |
| 构建产物 | `WorkCalendarView-FBfYRGrm.css` / `WorkCalendarView-DUlDP_nP.js` |

## 四、说明

- 并排分列时卡片是**半透明**的，FullCalendar 会把分列事件按 60%/… 宽度叠在一起，因此透过上层卡片能看到下层卡片的文字（视觉上会有点糊）。这是「半透明 + 多事项并存」的固有取舍，本次未改动配色透明度。
- 月份视图（`dayGrid`）未启用容器查询，卡片仍是内容全展示（月视图高度由内容撑开，不会挤）。
