## 三、内部端七步全流程（核心验证）

> 使用业务账号 demo/demo123（或 admin）登录后访问 http://123.56.9.243/bidding

### 3.1 需求征集（阶段1）— 企业需求申报（3 tab 抽屉 + 企业档案）

| # | 步骤 | 预期 |
|---|---|---|
| 3.1.1 | 点击「登记需求」 | 打开右侧抽屉「企业需求申报」：渐变蓝标题栏（icon+标题）、底部按钮居中，内部 **3 个 tab：企业概况 / 需求描述 / 合作意向**，tab 标题栏滚动时冻结 |
| 3.1.2 | 企业概况 tab：切换「新建企业」→ 填写企业名称（必填）、地址、资质荣誉（多选）、行业、注册资本、成立时间、人员规模、性质、主要产品或服务、上年度营收、联系人及职务、手机号码 | 全部正常录入；多选悬停 icon 有提示 |
| 3.1.3 | 企业概况 tab：切换「选择已有企业」→ 搜索并选择 | 下拉列出已存企业；选择后显示「已选择：xxx」提示；切换「新建企业」可录入新企业 |
| 3.1.4 | 需求描述 tab：需求名称（必填，80字上限）、主要技术难点 / 技术指标 / 研究内容（各 1000 字上限，textarea 5 行） | 字数超限被拦截，字数统计显示 |
| 3.1.5 | 合作意向 tab：拟短期/长期合作方式（多选）、意向专家（选"有"显示专家及单位输入框） | 正常 |
| 3.1.6 | 负向：需求名称/企业名称（新建模式）或企业选择（选择模式）缺失时保存 | 提示必填，不提交 |
| 3.1.7 | 保存成功 | 列表出现记录；**企业档案自动建立**（管理端企业下拉可见）；字段按申报表三部分存储 |
| 3.1.8 | 再次登记第二个需求，选择同一企业 | 复用企业档案，无需重填企业信息（1 企业多需求） |
| 3.1.9 | 编辑需求信息 | 抽屉回显（有档案→选择模式显示已选企业；无档案→新建模式回填） |
| 3.1.10 | 真实场景：按正大种业申报表录入（企业：襄阳正大种业股份有限公司；需求：耐热高蛋白玉米新品种选育及应用；意向专家：严建兵、邱法展） | 全部字段保存并可回读 |

### 3.2 专家论证（阶段2）

| # | 步骤 | 预期 |
|---|---|---|
| 3.2.1 | 详情内点击「提交专家论证」 | 阶段推进到「专家论证」，操作区变为「论证通过」「论证驳回」 |
| 3.2.2 | 点击「论证通过」，添加专家（姓名/单位/职称）、填写论证意见与结论 | 保存后阶段推进到「发榜公告」 |
| 3.2.3 | （负向用例）在阶段3 点击「提交专家论证」 | 后端返回 400「当前阶段为发榜公告，不允许执行…」，界面提示错误 |

### 3.3 发榜公告（阶段3）

| # | 步骤 | 预期 |
|---|---|---|
| 3.3.1 | 点击「发布公告」，不填揭榜截止日期直接确认 | 提示「必须填写揭榜截止日期」 |
| 3.3.2 | 填写悬赏金额/揭榜截止日期（建议设为未来日期）/揭榜条件后确认 | 发布成功，阶段不变（仍为发榜公告），公告信息卡片显示已发布 |
| 3.3.3 | 回到门户页刷新榜单列表 | **已发布的榜单出现在门户**（发榜公告对外可见），标记「揭榜中」 |
| 3.3.4 | 匿名点击该榜单详情 | 可见需求描述/悬赏/揭榜条件；「提交揭榜申请」需登录提示 |

### 3.4 揭榜评审（阶段4，含对外申请）

| # | 步骤 | 预期 |
|---|---|---|
| 3.4.1 | 在门户注册揭榜方账号（单位/联系人/邮箱/密码） | 注册成功提示回执邮件；若 SMTP 已配置，注册邮箱收到「注册成功通知」 |
| 3.4.2 | 门户登录后进入榜单详情，填写技术方案/团队优势/报价，提交申请 | 提交成功，提示回执邮件；邮箱收到「揭榜申请已提交」回执（SMTP 配置时） |
| 3.4.3 | 再次对同一榜单提交申请 | 被拦截「您已提交过该榜单的揭榜申请」 |
| 3.4.4 | 内部端详情→揭榜评审面板 | 可见该揭榜申请，来源标记「外部提交」 |
| 3.4.5 | 内部端点击「编辑/评分」给该申请评分 | 保存成功，评分显示 |
| 3.4.6 | 内部端点击「截止揭榜」 | 阶段推进到「揭榜评审」 |
| 3.4.7 | 内部端点击「确定揭榜方」，选中该申请并填评审结论 | 阶段推进到「任务签订」；该申请状态变「已中标」，其他申请变「未中标」 |
| 3.4.8 | （负向用例）未选择揭榜方直接确认 | 提示「请选择要确定的揭榜申请」 |

### 3.5 任务签订（阶段5）

| # | 步骤 | 预期 |
|---|---|---|
| 3.5.1 | 点击「签订任务书」，填任务经费/期限/签订日期/备注 | 阶段推进到「过程管理」；任务信息卡片显示已签订与揭榜方名称 |
| 3.5.2 | 新增 2 条里程碑（内容/计划完成时间） | 里程碑表格出现 2 行 |

### 3.6 过程管理（阶段6）

| # | 步骤 | 预期 |
|---|---|---|
| 3.6.1 | 将一条里程碑状态改为「已完成」并填完成说明 | 状态变为已完成，实际完成时间自动填充 |
| 3.6.2 | 将另一条改为「已延期」 | 状态正确显示 |
| 3.6.3 | 添加一条服务记录（如「电话回访企业」） | 全周期时间线新增记录，类型「服务记录」 |
| 3.6.4 | 点击「实施完成」 | 阶段推进到「绩效评价」 |

### 3.7 绩效评价（阶段7）

| # | 步骤 | 预期 |
|---|---|---|
| 3.7.1 | 点击「绩效评价」，只填等级不填评分 | 提示「绩效评价必须填写评分与等级」 |
| 3.7.2 | 填评分 92 / 等级「优秀」/ 评价报告后确认 | 评价完成，卡片显示评分与等级 |
| 3.7.3 | 全周期时间线 | 已自动记录每次阶段流转（系统流转类型）与人工服务记录 |

### 3.8 揭榜方查看项目进展（信息隔离）

| # | 步骤 | 预期 |
|---|---|---|
| 3.8.1 | 门户登录揭榜方账号 → 我的中心 → 我的申请 | 申请状态「已中标」，项目阶段显示当前阶段名 |
| 3.8.2 | 点击「查看」申请详情 | 中标后可看到：任务书信息、里程碑核查表（状态着色）、项目进展时间线、绩效评价结果（评分92/优秀） |
| 3.8.3 | （信息隔离）注册第二个揭榜方账号登录 | 我的申请列表为**空**，看不到第一个账号的申请 |
| 3.8.4 | 内部端登出后匿名访问 `/api/bidding/my-applications` | 返回 401 请先登录 |
